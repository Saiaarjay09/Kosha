Kosha

Encrypted Store · Zero Knowledge

A database and a filing system in one, where the server holds only bytes it cannot read.

Open Kosha

https://kosha.taila6d3cb.ts.net

That address lives on a private Tailscale network. It opens on any device signed in to that tailnet, and is invisible to everyone else — which is why this page, not the app, is the part that is always reachable.

What it is

Most tools make you choose. A database gives you real queries but wants your data in tables you define up front. A file store takes anything but can only tell you a file's name and size. Kosha is both halves at once: drop a spreadsheet into a folder and it is filed, converted, and queryable in SQL — all three, from one action.

  • Folders have a type. A folder declares that it holds CSV, or Excel, or JSON, or PNG. Anything you put in is converted to match, and anything that genuinely cannot be is refused with a reason rather than silently accepted.
  • You define how things are filed. A folder's storage template — something like {yyyy}/{mm}/{slug}.{ext} — decides the name and path every file lands under, so a filing convention is a setting rather than a habit you have to keep.
  • Real SQL, not an imitation. SQLite itself, compiled to WebAssembly and running in your browser tab. Joins, GROUP BY, views, triggers, window functions, transactions.
  • Your filing system is queryable too. Folders and files live in the same database as your data, so "which CSVs in /invoices have more than a thousand rows" is just a SELECT.
  • A query builder that shows its work. Answer a few questions and it writes the SQL into the editor where you can read it, change it, and eventually stop needing it.

How the encryption works

Your password is turned into two independent keys. One goes to the server, which uses it only to decide whether to let you in. The other never leaves your browser, and it is the only thing that can decrypt your vault. Neither can be computed from the other.

So the server stores an encrypted SQLite database and a pile of encrypted files, and has no way to read either. That is also why SQL runs in your browser rather than on the server: a server that could index or filter your rows would be a server that could read them.

The honest caveat: the app's code is delivered by that same server on every page load. Zero-knowledge storage protects your data at rest and in transit; it cannot protect you from a server that serves you altered code before you type your password. That is true of every browser-delivered encryption tool, and it is stated here rather than left out.

Run your own

git clone https://github.com/Saiaarjay09/kosha.git
cd kosha
pip3 install -r requirements.txt
python3 -m uvicorn server.server:app --port 8711

# then put it on your tailnet:
./deploy/setup-tailscale.sh serve

Everything is self-hosted and there are no third-party services, no API keys and no accounts anywhere but your own machine. The only outside code is SQLite and a spreadsheet reader, both vendored into the repository so the app works with no network at all.
